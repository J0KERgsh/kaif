# План ручного тестирования перед защитой

## Подготовка
1. Установить Node.js 22.13+ и зависимости в `backend` и `frontend`.
2. Скопировать `.env.example` в `.env` в обеих папках.
3. Выполнить `npm run seed` в backend.
4. Запустить backend и frontend в двух окнах CMD.
5. Проверить `http://localhost:4000/api/health`.

## Сценарии
- [ ] Главная открывается без ошибок в консоли, локальные SVG-иллюстрации загружаются.
- [ ] Слайдер переключается автоматически, кнопками и точками.
- [ ] Каталог загружает данные из API; поиск находит имя и описание.
- [ ] Фильтры по виду, полу, возрасту и статусу работают совместно.
- [ ] Сортировка меняет порядок; пагинация переключает страницы.
- [ ] Карточка питомца показывает корректный ID, фото, описание, здоровье и статус.
- [ ] Заявку с валидными данными можно отправить; отсутствующие поля блокируются.
- [ ] Сервер отклоняет неверный email, телефон и недоступного питомца.
- [ ] Вход администратора работает с учётными данными из локального README.
- [ ] Без JWT admin API отвечает 401.
- [ ] Администратор может добавить питомца с несколькими JPG/PNG/WebP, изменить статус и удалить карточку.
- [ ] Заявки видны в панели, статус заявки меняется, CSV скачивается.
- [ ] Прямое открытие `/animals/1`, `/adopt/1`, `/admin` работает после настройки SPA fallback.
- [ ] Неизвестный путь показывает страницу 404.
- [ ] Проверить ширины 390 px, 768 px и 1440 px.
- [ ] Проверить Chrome и Firefox/Edge.
- [ ] Переключение темы сохраняется после перезагрузки.
- [ ] При включённом системном `prefers-reduced-motion` анимации минимизированы.

## Автоматические проверки
- Из корня: `node scripts/check-imports.mjs`.
- В `backend`: `npm test`; `node --check src/server.js`; `node --check src/db.js`; `node --check src/seed.js`.
- В `frontend`: `npm run build`.

Отметки ручного тестирования заполняются после запуска проекта в локальном браузере; не отмечайте пункты как пройденные без фактической проверки.
